Solvers

ProbNumDiffEq.jl provides various probabilistic ODE solvers based on extended Kalman filtering and smoothing.

Which solver should I use?

  • Use the EK1 to get the best uncertainty quantification and to solve stiff problems.
  • Use the DiagonalEK1 for high-dimensional problems for which the EK1 is too expensive.
  • Use the MatfreeEK1 for problems that are both high-dimensional and stiff, if you can provide Jacobian-vector and vector-Jacobian products.
  • Use the EK0 to get the fastest runtimes and to solve high-dimensional problems.

The EK1 and the DiagonalEK1 are compatible with DAEs in mass-matrix ODE form. They also specialize on second-order ODEs: If the problem is of type SecondOrderODEProblem, it solves the second-order problem directly; this is more efficient than solving the transformed first-order problem and provides more meaningful posteriors [1].

API

ProbNumDiffEq.EK1 — Function
EK1(; order=3,
      smooth=true,
      prior=IWP(order),
      diffusionmodel=DynamicDiffusion(),
      initialization=TaylorModeInit(num_derivatives(prior)),
      kwargs...)

Gaussian ODE filter with first-order vector field linearization.

This is a semi-implicit, L-stable ODE solver so it can handle stiffness quite well Tronarp et al. (2019), and it generally produces more expressive posterior covariances than the EK0. However, as typical implicit ODE solvers it scales cubically with the ODE dimension Krämer et al. (2022), so if you're solving a high-dimensional non-stiff problem you might want to give the EK0 a try.

The EK1 is the ODEFilter with linearization=FullJacobian(); see there for all keyword arguments.

Examples

julia> solve(prob, EK1())

ProbNumDiffEq.DiagonalEK1 — Function
DiagonalEK1(; order=3,
              smooth=true,
              prior=IWP(order),
              diffusionmodel=DynamicDiffusion(),
              initialization=TaylorModeInit(num_derivatives(prior)),
              kwargs...)

Gaussian ODE filter with first-order vector field linearization and diagonal Jacobian approximation.

A semi-implicit solver that approximates the Jacobian as diagonal, using a block-diagonal covariance representation to achieve linear scaling with the ODE dimension Krämer et al. (2022). This makes it suitable for high-dimensional problems where the full EK1 would be too expensive.

Settings that only dense covariances can represent, such as an IOUP or Matern prior or a non-diagonal mass matrix, throw an error unless you pass `covariancefactorization=DenseCovariance`, as dense covariances scale cubically with the problem size._

Providing a Jacobian for linear scaling

For truly linear O(d) time and memory complexity, provide both a custom Jacobian function and a diagonal jac_prototype in your ODEFunction:

ODEFunction(f; jac=jac, jac_prototype=Diagonal(ones(d)))

Without these, the solver falls back to computing and storing the full d×d Jacobian via automatic differentiation and only extracting the diagonal afterwards, resulting in O(d²) time and memory for the Jacobian computation.

The DiagonalEK1 is the ODEFilter with linearization=DiagonalJacobian(); see there for all keyword arguments.

Examples

julia> solve(prob, DiagonalEK1())

ProbNumDiffEq.MatfreeEK1 — Function
MatfreeEK1(; order=3, nprobes=2(num_derivatives(prior)+1), diagonal_jacobian=nothing,
             prior=IWP(order), diffusionmodel=DynamicDiffusion(), smooth=true,
             initialization=TaylorModeInit(num_derivatives(prior)), kwargs...)

Matrix-free Gaussian ODE filter with first-order vector field linearization.

Like the EK1, it linearizes the ODE vector field with its Jacobian, which makes it suitable for stiff problems. But it accesses the Jacobian only through products, solves the linear systems with Krylov methods, and estimates a block-diagonal posterior covariance from random probes, so that its cost per step scales linearly with the ODE dimension Bosch (2026). The ODE function needs both products, as ODEFunction(f; jvp, vjp) with jvp(Jv, v, u, p, t) and vjp(Jᵀv, v, u, p, t).

Arguments

  • nprobes: the number of probes for the posterior covariance.
  • diagonal_jacobian: optionally, a function (out, u, p, t) that writes the diagonal of the Jacobian into out. The linear solves then use a cheaper preconditioner built from it, instead of one estimated from probes. This preconditioner is more approximate. It works well when the Jacobian is dominated by its diagonal, as for many discretized PDEs. When the off-diagonal entries dominate, it is a worse preconditioner, and the solution can become less accurate.

All other keyword arguments of ODEFilter are supported, except observation noise and priors other than IWP. Of the multivariate diffusions, only the FixedMVDiffusion with calibrate=false is supported. Mass matrices and second-order ODEs are not supported yet.

The probes are drawn from the keyword rng of solve if the installed OrdinaryDiffEq supports it, and otherwise from Random.default_rng(). sol.pnstats counts the products and the linear solves. Its log-likelihood is NaN.

Examples

julia> solve(prob, MatfreeEK1())

ProbNumDiffEq.EK0 — Function
EK0(; order=3,
      smooth=true,
      prior=IWP(order),
      diffusionmodel=DynamicDiffusion(),
      initialization=TaylorModeInit(num_derivatives(prior)),
      kwargs...)

Gaussian ODE filter with zeroth-order vector field linearization.

This is an explicit ODE solver. It is fast and scales well to high-dimensional problems Krämer et al. (2022), but it is not L-stable Tronarp et al. (2019). So for stiff problems, use the EK1.

Whenever possible this solver will use a Kronecker-factored implementation to achieve its linear scaling and to get the best runtimes. This can currently be done only with an IWP prior (default), with a scalar diffusion model (either DynamicDiffusion or FixedDiffusion). Otherwise it uses block-diagonal covariances, which also scale linearly, for example with a multivariate diffusion model or a Diagonal mass matrix.

Settings that only dense covariances can represent, such as an IOUP or Matern prior or a non-diagonal mass matrix, throw an error unless you pass `covariancefactorization=DenseCovariance`, as dense covariances scale cubically with the problem size._

The EK0 is the ODEFilter with linearization=ZeroJacobian(); see there for all keyword arguments.

Examples

julia> solve(prob, EK0())

ProbNumDiffEq.ODEFilter — Type
ODEFilter(; linearization, order=3, prior=IWP(order), diffusionmodel=DynamicDiffusion(),
          smooth=true, initialization=TaylorModeInit(num_derivatives(prior)),
          pn_observation_noise=nothing, covariance_factorization=nothing,
          autodiff=AutoForwardDiff(), standardtag=true, concrete_jac=nothing)

Gaussian ODE filter, the primary class of probabilistic ODE solvers in ProbNumDiffEq.jl. Solvers such as EK0, EK1 and DiagonalEK1 are short-hands for particular kinds of ODEFilters. Using this constructor directly allows for the most flexibility.

Arguments

  • linearization::AbstractLinearization: How the ODE vector field is linearized: ZeroJacobian() as in the EK0, DiagonalJacobian() as in the DiagonalEK1, FullJacobian() as in the EK1, or MatrixFreeJacobian() as in the MatfreeEK1. Iterated wraps one of them to linearize at the posterior.
  • order::Integer: Order of the default integrated Wiener process (IWP) prior.
  • prior::AbstractGaussMarkovProcess: Prior to be used by the ODE filter. By default, an order-times integrated Wiener process prior IWP(order). See also: Priors.
  • diffusionmodel::ProbNumDiffEq.AbstractDiffusion: See Diffusion models and calibration.
  • smooth::Bool: Turn smoothing on/off; smoothing is required for dense output.
  • initialization::ProbNumDiffEq.InitializationScheme: See Initialization.
  • pn_observation_noise: Covariance of noise on the observation of the ODE, as a number, a UniformScaling or a matrix; nothing for none.
  • covariance_factorization: IsometricKroneckerCovariance, BlockDiagonalCovariance or DenseCovariance. By default, the most structured one that all other settings and the problem's mass matrix support. The EK0 and the DiagonalEK1 use DenseCovariance only when it is set here, since dense covariances scale cubically with the ODE dimension.
  • autodiff: How to compute the Jacobian if the linearization or the prior need one, e.g. AutoForwardDiff() or AutoFiniteDiff() from ADTypes.jl.
  • standardtag, concrete_jac: As for the implicit solvers of OrdinaryDiffEq.jl.

For compatibility with OrdinaryDiffEq 6, the keywords chunk_size, diff_type and autodiff=true/false are folded into autodiff.

Examples

julia> solve(prob, ODEFilter(linearization=FullJacobian(), order=5))

Iterated linearization

ProbNumDiffEq.Iterated — Type
Iterated(linearization; maxiters=20, tol=1e-2)

Linearize the ODE at the posterior instead of the prediction, by linearizing and updating again and again until the solution changes by less than tol (relative to abstol and reltol), but at most maxiters times. This is the iterated extended Kalman filter Bosch (2026).

With adaptive steps, a step that does not converge is rejected. With fixed steps, it is accepted and counted in sol.stats.nnonlinconvfail.

Examples

julia> solve(prob, ODEFilter(linearization=Iterated(DiagonalJacobian())))

Probabilistic Exponential Integrators

ProbNumDiffEq.ExpEK — Function
ExpEK(; L, order=3, kwargs...)

Probabilistic exponential integrator

Probabilistic exponential integrators are a class of integrators for semi-linear stiff ODEs that provide improved stability by essentially solving the linear part of the ODE exactly. In probabilistic numerics, this amounts to including the linear part into the prior model of the solver.

ExpEK is therefore just a short-hand for EK0 with IOUP prior and dense covariances:

ExpEK(; order=3, L, kwargs...) =    EK0(; prior=IOUP(order, L), covariance_factorization=DenseCovariance, kwargs...)

See also RosenbrockExpEK, EK0, EK1.

Arguments

  • L: Rate parameter of the IOUP prior, i.e. the linear part of the ODE.
  • order::Integer: Order of the IOUP prior.

All other keyword arguments of ODEFilter are supported, except prior.

Examples

julia> prob = ODEProblem((du, u, p, t) -> (@. du = - u + sin(u)), [1.0], (0.0, 10.0))julia> solve(prob, ExpEK(L=-1))

ProbNumDiffEq.RosenbrockExpEK — Function
RosenbrockExpEK(; order=3, kwargs...)

Probabilistic Rosenbrock-type exponential integrator

A probabilistic exponential integrator similar to ExpEK, but with automatic linearization along the mean numerical solution. This brings the advantage that the linearity does not need to be specified manually, and the more accurate local linearization can sometimes also improve stability; but since the "prior" is adjusted at each step the probabilistic interpretation becomes more complicated.

RosenbrockExpEK is just a short-hand for EK1 with locally-updated IOUP prior:

RosenbrockExpEK(; order=3, kwargs...) = EK1(; prior=IOUP(order, update_rate_parameter=true), kwargs...)

See also ExpEK, EK0, EK1.

Arguments

  • order::Integer: Order of the IOUP prior.

All other keyword arguments of ODEFilter are supported, except prior.

Examples

julia> prob = ODEProblem((du, u, p, t) -> (@. du = - u + sin(u)), [1.0], (0.0, 10.0))julia> solve(prob, RosenbrockExpEK())
